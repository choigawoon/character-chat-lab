# 캐릭터 챗 실험실 (character-chat-lab)

미리 짜 둔 세계 · 상황극에 들어가 마음대로 개입하며, 작은 모델(기본 Gemma 4 E2B · E4B)이 한국어로 캐릭터를 얼마나 잘 연기하는지 연구하는 웹앱이다. 캐릭터 챗 서비스의 '상황극 플레이' 모양을 가장 작게 만들고, 모델에 보내는 내용을 그대로 확인하는 디버그 화면을 붙였다.

## 일을 나누는 방식

| 누가 | 무엇을 | 언제 |
|---|---|---|
| 최상위 모델(미리) | 세계관 · 인물 시트(말투 예시 포함) · 상황 · 첫 장면 · 숨은 전개 · 처음부터 기억할 사실 · 로어북 | 상황극을 만들 때 한 번 — `content/worlds/*.json` |
| 작은 모델(E2B · E4B) | 매 턴 캐릭터 대사와 장면 진행 | 대화할 때마다 |
| 기억 모델(`MEMORY_MODEL`) | 오래된 대화를 줄거리로 접기 | 접지 않은 메시지가 24개를 넘으면 자동, 또는 '지금 접기' |
| 이 서버(모델 없이) | 로어북 고르기 — 최근 대화에 나온 낱말에 걸린 설정만 넣는다 | 매 턴 |

작은 모델은 긴 설정을 다 소화하지 못하고 앞 이야기를 잊는다. 그래서 어려운 글쓰기는 미리 해 두고, 매 턴에는 필요한 것만 골라 넣는다.

## 상황극 (기본 18편)

| 세계 | 상황극 | 나는 |
|---|---|---|
| 해리 포터 AU — 여자가 된 말포이 | 슬리데린 테이블의 낯선 여학생 · 도서관 금지 구역 · 해독 직전 마지막 밤 | 해리 · 헤르미온느 |
| 반지의 제왕 AU — 은발의 간달프 | 백엔드의 밤 · 달리는 조랑말 여관 · 모리아 서문 | 프로도 · 샘 |
| 사조영웅전 | 장가구의 만두 도둑 · 홍칠공의 항룡십팔장 · 도화도의 사윗감 시험 | 곽정 |
| 감자(김동인) | 칠성문 밖으로 밀려나는 날 · 왕서방 혼례 날 밤 | 이웃 — 복녀의 운명을 바꿀 수 있다 |
| 소나기(황순원) | 징검다리 위의 하얀 조약돌 · 수숫단 아래, 소나기 | 소년 |
| 이 멋진 세계에 축복을! | 자이언트 토드 첫 퀘스트 · 폭렬 산책 · 베르디아의 성 앞 | 카즈마 · 신입 모험가 |
| 오리지널 | 방과 후 빈 교실 · 사라진 초판 동화책 | 같은 반 학생 · 서점 주인 |

원작이 있는 세계는 설정 · 이름만 빌려 새로 쓴 팬픽 설정이고, 원작 문장은 옮기지 않았다. 모든 설정은 모델에게 성적 묘사와 잔혹 묘사를 하지 말라고 지시한다. 원작이 가난 · 매춘 · 살인을 다루는 「감자」는 매춘을 '체면과 정직을 판 쉬운 돈의 유혹'으로 바꾸고, 결말의 살인은 장면을 그리지 않고 '그날 밤의 비극'으로만 닫게 했다. 모델이 늘 지킨다는 보장은 아니다. 새 세계를 더하는 규약은 [content/SCHEMA.md](content/SCHEMA.md) 에 있다.

## 돌리기

```bash
cp .env.example .env      # 모델 서버 연결을 고른다(아래)
npm run dev               # http://localhost:8795
npm test
```

의존성은 없다(node 22.9 이상 표준 라이브러리만). 대화 · 기억 · 직접 만든 캐릭터는 브라우저(localStorage)에만 저장하고, 이 앱의 서버는 아무것도 저장하지 않는다. 연결한 모델 서버가 요청을 기록하는지는 그 서버의 설정을 따른다.

## 모델 연결 (.env)

| LLM_API | 무엇 | LLM_BASE_URL 예 |
|---|---|---|
| `ollama` (기본) | 로컬 Ollama 고유 API(`/api/chat`, 생각 모드 끔) | `http://localhost:11434` |
| `openai` | OpenAI 호환 `/chat/completions` (+ `LLM_API_KEY`, 생각 모드 끄기 `REASONING_EFFORT` 기본 `none`) | `http://localhost:11434/v1` · `https://example.com/v1` |
| `textgen` | `{model, messages, temperature, max_tokens}` 를 받아 `{text, usage}` 로 답하는 관문 | 엔드포인트 전체 주소 |

- `MODELS` — 화면의 모델 버튼 목록. `key` 는 이 앱 안의 이름(브라우저에 저장되는 값), `label` 은 버튼 글자, `id` 는 모델 서버가 아는 모델 이름이다. 예: `MODELS=[{"key":"e4b","label":"E4B","id":"gemma4:e4b"},{"key":"q3","label":"Qwen3 8B","id":"qwen3:8b"}]`. 브라우저에 고른 모델이 저장돼 있지 않으면 목록의 마지막 모델이 골라진다(`DEFAULT_MODEL` 로 바꿀 수 있다).
- `MEMORY_MODEL` — 기억 접기에 쓸 모델이다. 기억 접기는 오래된 대화를 [줄거리 · 관계 · 약속 · 지금] 형식으로 요약하고, 요약한 원본 메시지 대신 그 요약을 모델에 넣는 일이다. 비우면 `MODELS` 의 기본 모델(`DEFAULT_MODEL`, 없으면 목록의 마지막) id 를 쓴다. 더 큰 모델을 두는 것은 작은 모델이 앞 이야기를 놓친다는 첫 실측에서 나온 가정이고, 요약 품질 차이는 아직 재지 않았다(아래 '해 볼 것'). `MEMORY_LLM_API` · `MEMORY_LLM_BASE_URL` · `MEMORY_LLM_API_KEY` 를 주면 기억 접기만 다른 모델 서버(예: 클라우드의 최상위 모델)로 보낸다. 기억 모델을 대화 모델과 같은 GPU 에 두면, GPU 메모리가 모자랄 때 둘 중 하나를 내리고 다시 올리느라 응답이 수십 초 늦어질 수 있다(4090 에서 30B 모델로 접을 때 실제로 그랬다).
- `LLM_HEADERS` — 관문이 요구하는 머리글(JSON). `LLM_USER_HEADER` — 사용자 구분 머리글 이름(값은 브라우저 id 의 해시).
- `TEMPERATURE` · `MAX_TOKENS` — 생성 설정(기본 0.8 · 600).

## 화면

- **첫 화면** — 세계별 상황극 카드. '직접 만든 캐릭터'로 설정집 · 첫 인사만 적은 일대일 캐릭터도 만들 수 있다.
- **상황극 소개** — 지금 장면, 등장인물, 해 볼 수 있는 것, 내 역할을 보여 준다. 역할의 이름과 한 줄 소개를 바꾼 뒤 '시작하기'나 '이어 하기'를 누른다.
- **플레이**
  - 말과 행동(`*행동*`)으로 개입한다. 다른 인물은 「이름: 대사」로 끼어든다.
  - **🎬 연출** — 켜고 보내면 대사가 아니라 장면 지시가 된다(예: "갑자기 비가 쏟아진다"). 모델은 지시를 반영해 다음 장면을 쓴다.
  - **🧠 기억** — 모델이 매 턴 받는 기억은 셋이다. 처음부터 기억할 사실, 내가 적은 메모, 지난 줄거리(앞 대화를 접은 것)다. 메모와 줄거리는 직접 고칠 수 있고 '지금 접기'로 바로 접을 수 있다. 접힌 자리는 대화 안에 표시된다.
  - **🔍 맥락** — 다음에 보낼 메시지를 순서대로 보여 준다. 맨 앞 `system` 메시지(모델에 규칙과 설정을 주는 메시지)는 구획으로 나뉘어 색별로 나오고, 구획마다 글자 수와 비율이 보인다. 구획은 대답 규칙 · 세계관 · 등장인물 · 지금 장면 · 진행 메모 · 기억 · 로어북(최근 대화에 나온 낱말에 걸린 설정 조각만 그 턴에 골라 넣는 것) · 다시 한 번(핵심 규칙을 끝에서 한 번 더) 순서다. 턴 기록에는 턴마다 입력 · 출력 토큰 그래프, 그 턴에 걸린 로어북 낱말, '이 턴에 보낸 것 보기'가 있다. 대화(`/api/chat`)와 맥락 보기(`/api/preview`)는 같은 함수(`buildRequest`)로 맥락을 만들므로, 맥락 보기에 보이는 메시지가 모델에 보내는 메시지와 같다.

## 맥락을 만드는 순서

`system` = [대답 규칙] [세계관] [등장인물 시트] [지금 장면] [진행 메모 — 사용자에게 말하지 않는다] [기억] [참고 — 대화에 나온 로어북] [다시 한 번 — 핵심 규칙]
→ `assistant` 첫 장면(줄거리로 접은 뒤에는 넣지 않는다) → 접지 않은 지난 대화(최근 40개) → `user` 이번 말 또는 연출 지시.

핵심 규칙을 맨 앞과 맨 끝에 두 번 넣은 것은, 긴 system 메시지의 앞부분 지시는 끝에서 다시 말해야 작은 모델이 지키기 쉽다는 가정 때문이다. 첫 실측에서 설정집 규칙('3~6문장')을 넘기거나 모자란 답이 많았던 것이 출발점이고, 반복의 효과는 아직 재지 않았다(아래 '해 볼 것'). 코드는 [server/main.mjs](server/main.mjs) `scenarioSections` · `buildMessages` · `matchLore` · `memoryPrompt` 다.

## 연구 메모

- 첫 실측(MacBook Air M4 · Ollama · 한국어 롤플레잉 2편, 각 8턴, 설정집만 넣은 일대일 대화):
  - E2B — 간달프 편에서 뜻 없는 말 '그저께'를 다섯 번 넣었고, 8턴째 "처음에 나를 누구로 생각했나"에 "시녀라 여겼지"라고 틀리게 답했다(실제로는 빌보의 손님으로 여겼다).
  - E4B — 간달프 편에서 외모 설정(은발의 여인)과 1턴 기억("빌보의 손님이라 여긴")을 맞혔다. 말포이 편에서는 '포터' 호칭과 반말 말투를 지켰지만, 4 · 5턴에서 상대를 "그레인저"라고 잘못 불렀고 8턴째 첫 질문을 기억하지 못했다.
- 상황극 틀(세계관 · 시트 · 숨은 전개 · 로어북)로 바꾼 뒤 E4B 첫 턴: 세계마다 말투(무협 하오체 · 평안도 맛 사투리 · 라노벨 말버릇)를 지켰고, 입력은 2,400~3,300토큰이었다.
- 속도: RTX 4090 · Ollama · `gemma4:e4b` 기본판에서 154토큰 답을 요청부터 응답 완료까지 1.0초에 냈다. MacBook Air M4 에서는 같은 모델이 초당 약 47토큰을 생성했다.
- 해 볼 것:
  - 숨은 전개를 몇 턴째에 꺼내는지, 사용자가 이끌 때 전개를 덮어쓰는지.
  - 로어북 항목 수 · 길이를 바꿨을 때 설정 실수가 줄어드는지와, 그 대신 입력 토큰이 얼마나 느는지.
  - 기억 접기를 작은 모델 · 큰 모델로 했을 때 20턴 뒤 앞 사건을 맞히는 비율.
  - 끝의 '다시 한 번' 구획을 빼고 돌렸을 때 문장 수 · 호칭 규칙을 지키는 비율이 달라지는지.
  - 같은 대사 목록으로 모델끼리 돌려 호칭 실수 · 기억 실수 · 반복 횟수를 세어 비교.
