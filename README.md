# 캐릭터 챗 실험실 (character-chat-lab)

설정집을 넣은 캐릭터와 한국어로 대화하며 작은 모델(기본 Gemma 4 E2B · E4B)의 캐릭터 롤플레잉을 연구하는 웹앱. 캐릭터를 고르고 대화하는 화면(캐릭터 챗 서비스의 가장 작은 모양)에, 모델에 보내는 내용을 그대로 확인하는 디버그 화면을 붙였다.

## 돌리기

```bash
cp .env.example .env      # 모델 서버 연결을 고른다(아래)
npm run dev               # http://localhost:8795
npm test
```

의존성은 없다(node 22.9 이상 표준 라이브러리만). 대화 · 직접 만든 캐릭터 · '나는 누구?' 소개는 브라우저(localStorage)에만 저장하고 서버는 아무것도 저장하지 않는다.

## 모델 연결 (.env)

| LLM_API | 무엇 | LLM_BASE_URL 예 |
|---|---|---|
| `ollama` (기본) | 로컬 Ollama 고유 API(`/api/chat`, 생각 모드 끔) | `http://localhost:11434` |
| `openai` | OpenAI 호환 `/chat/completions` (+ `LLM_API_KEY` · 생각 모드 끄기 `REASONING_EFFORT`, 기본 `none`) | `http://localhost:11434/v1` · `https://example.com/v1` |
| `textgen` | `{model, messages, temperature, max_tokens}` → `{text, usage}` 관문 | 엔드포인트 전체 주소 |

- `LLM_HEADERS` — 관문이 요구하는 머리글(JSON). `LLM_USER_HEADER` — 사용자 구분 머리글 이름(값은 브라우저 id 의 해시).
- `MODELS` — 화면의 모델 버튼 목록. `key` 는 이 앱 안의 이름(브라우저에 저장되는 값), `label` 은 버튼 글자, `id` 는 모델 서버가 아는 모델 이름이다. 예: `MODELS=[{"key":"e4b","label":"E4B","id":"gemma4:e4b"},{"key":"q3","label":"Qwen3 8B","id":"qwen3:8b"}]`. 모델을 나란히 비교하려면 여기 더한다. 브라우저에 고른 모델이 저장돼 있지 않으면 목록의 마지막 모델이 골라진다(`DEFAULT_MODEL` 로 바꿀 수 있다).
- `TEMPERATURE` · `MAX_TOKENS` — 생성 설정(기본 0.8 · 600).

## 화면

- **첫 화면** — 캐릭터 카드(기본 넷) · '캐릭터 만들기'(설정집 · 첫 인사 · 내 역할 · 이모지) · '나는 누구?'(모든 캐릭터에게 알려 줄 내 소개).
- **대화** — 모델 고르기 · 다시 생성 · 처음부터. 답마다 모델 · 걸린 시간 · 출력 토큰. `*행동*` 은 기울인 회색.
- **🔍 맥락** — 두 가지를 보여 준다.
  - '다음에 보낼 것': 지금 보내면 모델에 들어갈 메시지(설정집 → 첫 인사 → 지난 대화 → 이번 말)의 원문 · 글자 수 · 구성 막대. 보내지는 않는다.
  - '턴 기록': 이미 받은 답마다 입력 · 출력 토큰 그래프와 '이 턴에 보낸 것 보기'(그 턴까지의 대화로 맥락을 다시 만들어 보여 준다).
  대화(`/api/chat`)와 맥락 보기(`/api/preview`)는 같은 함수(`buildRequest`)로 맥락을 만들므로, 맥락 보기에 보이는 메시지가 모델에 보내는 메시지와 같다. 직접 확인하려면 브라우저 개발자 도구 네트워크 탭에서 `/api/preview` 응답의 `parts` 를 보면 된다.

## 캐릭터

기본 캐릭터는 [characters.json](characters.json) — `system`(설정집) · `greeting`(첫 인사) · `you`(사용자가 맡는 역할) · 소개 칸. 원작 캐릭터 둘(해리포터 · 반지의 제왕)은 설정 하나를 바꾼 팬픽 설정(AU)이고 원작 문장은 옮기지 않았다. 네 설정집은 모두 모델에게 전연령 수위를 지키라고 지시한다(모델이 늘 지킨다는 보장은 아니다).

모델에 보내는 맥락은 `system`(설정집 + 내 소개), `assistant`(첫 인사), 지난 대화, `user`(이번 말) 순서다. 지난 대화는 사용자 · 캐릭터 메시지를 하나씩 세어 최근 40개만 보낸다. 코드는 [server/main.mjs](server/main.mjs) `buildMessages` 다.

## 연구 메모

- 처음 재 본 것(MacBook Air M4 · Ollama · 한국어 롤플레잉 2편, 각 8턴):
  - E2B — 간달프 편에서 뜻 없는 말 '그저께'를 다섯 번 넣었고, 8턴째 "처음에 나를 누구로 생각했나"에 "시녀라 여겼지"라고 틀리게 답했다(실제로는 빌보의 손님으로 여겼다).
  - E4B — 간달프 편에서 외모 설정(은발의 여인)과 1턴 기억("빌보의 손님이라 여긴")을 맞혔다. 말포이 편에서는 '포터' 호칭과 반말 말투를 지켰지만, 4 · 5턴에서 상대를 "그레인저"라고 잘못 불렀고 8턴째 첫 질문을 기억하지 못했다.
- 속도: RTX 4090 · Ollama · `gemma4:e4b` 기본판에서 154토큰 답을 요청부터 응답 완료까지 1.0초에 냈다. MacBook Air M4 에서는 같은 모델이 초당 약 47토큰을 생성했다.
- 해 볼 것:
  - 설정집 길이 · 모양(예시 대사 수, 규칙을 앞 · 뒤 어디에 두나)을 바꿨을 때 8턴 동안 호칭 · 말투가 얼마나 유지되나.
  - 첫 인사 장면을 바꿨을 때 첫 몇 턴의 분위기 · 길이가 어떻게 달라지나.
  - 지난 대화를 요약해 넣으면 입력 토큰은 얼마나 줄고 앞 대화 기억은 유지되나.
  - 같은 대사 목록으로 모델끼리 돌려 호칭 실수 · 기억 실수 · 반복 횟수를 세어 비교.
